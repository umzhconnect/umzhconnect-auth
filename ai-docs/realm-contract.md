# Realm contract

The realm configuration is the sandbox drop-in contract. Any change here must remain compatible with `umzhconnect-sandbox` unless intentionally diverging (document the reason in [realm-contract.md](realm-contract.md)).

## Fixed realm settings

| Item | Value |
|------|-------|
| Realm | `umzh-connect` |
| Issuer (published) | `http://localhost:8180/realms/umzh-connect` |
| Token lifetime | 300 s |

## Clients

All production clients are L2 (`private_key_jwt`). L1 (`client_secret`) is banned from production.

Production clients are generated by Terraform from `config/apps/` + `config/grants/` — there are no hardcoded client IDs. KC client ID format: `{org_id}--{app_id}--{server_key}`. See [config-model.md](config-model.md).

## Mappers (per M2M client)

Each M2M client has all four mappers attached:

| Mapper | Claim added | Source |
|--------|-------------|--------|
| `org-reference-mapper` | `extensions.umzhconnect.organization_reference` | Set by AS from the app's `org_reference` field — never by the client |
| `fhir-context-mapper` | `fhirContext` | Reads `authorization_details` from raw request; see [mapper.md](mapper.md) |
| `tenant-mapper` | `tenant` | Routing hint (`placer`/`fulfiller`) — sandbox artifact; confirm with UMZH whether to keep |
| `realm-roles` | `realm_access.roles` | Keycloak built-in |

## Scopes

Custom client scopes are declared in `config/scopes.yaml` and created by `scopes.tf`. All M2M hospital clients receive the `default_scopes` set automatically; `optional_scopes` are registered but not assigned by default.

Scope names follow the SMART Backend Services convention (`system/{Resource}.{interactions}`). The full list is in [`config/scopes.yaml`](../keycloak/config/scopes.yaml).

## Audience (`aud`) binding

Every M2M client carries a constant `aud` identifying the umzh-connect ecosystem as a whole (the realm issuer URL), via the `ecosystem-audience-mapper` protocol mapper on each client. Target-specific `aud` binding (RFC 8707) is deferred until Keycloak's `resource-indicators` support is non-experimental. There is no per-hospital inbound allow-list — any FHIR server in the realm accepts any token. See [ADR 0003](../docs/adr/0003-constant-ecosystem-audience.md).

## Roles

`admin`.

## Sandbox-only config (gate or remove for production)

- **`users.tf`** — `web-app` PKCE client with ROPC (`direct_access_grants_enabled = true`) and three demo users with hardcoded passwords. Remove or gate behind a flag.
- **`smart-*` scopes** in `scopes.tf` — user-facing consent screen scopes, not M2M. Remove or gate.
- **`ssl_required = "none"`** in `realm.tf:11` — must be `external` or `all` in production.
- **`start-dev`** in `docker-compose.yml` — disables all Keycloak production hardening; dev-only.

## Known divergences from the sandbox `realm-export.json`

| Setting | This repo | Sandbox | Reason |
|---------|-----------|---------|--------|
| `registrationAllowed` | `false` | `true` | No self-registration needed for M2M |
| `displayName` | `"UMZH Connect"` | `"UMZH Connect Sandbox"` | Intentional |
| Built-in scopes (`email`, `profile`, `roles`, …) | Present | Absent from export | Keycloak includes them by default; sandbox export skipped them |
